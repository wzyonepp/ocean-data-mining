## 4. 重点观察与边界诊断

对于 41002 从 2023-03-15 开始查询 1 天的例子，站点优先中位数约 3.034 ms，时间优先约 2.409 ms；元数据候选行组分别为 3 和 1。

单独读取候选行组后发现：站点优先第 4、10 号行组跨越站点边界，站点范围与时间范围分别都包含查询条件，但没有记录同时满足两者；第 5 号行组才包含实际匹配的 144 行。时间优先第 4 号行组包含相同的 144 行。行组编号从 0 开始。

这说明独立的逐列范围统计可能保留没有联合匹配记录的行组。它是本次样例中已检查到的现象，值得在后续实验中验证适用范围。

对于同站点 30 天查询，本次站点优先中位数约 3.104 ms、时间优先约 3.488 ms，但时间优先测量范围约 3.005—5.432 ms，存在波动；不能用这一个样例宣称已确认优劣反转或显著差异。

候选行组由元数据估算；边界诊断属于额外直接读取行组后的核对，均不代表 DuckDB 实际读取了哪些行组。计划中的行数也属于优化器估计，不当作实际扫描行数。

## 5. 运行条件与可复现文件

Python 3.12.14、PyArrow 26.0.1、DuckDB 2.0.0；单查询线程，UTC；ZSTD 级别 3，仅站点列字典编码，每行组上限 16,384 行。当前环境为 Linux，容器内存限制 8 GiB、CPU 配额约 2 核；这些运行条件不代表其他机器。

正确性检查、全文件读回及额外预热会使缓存变热；DuckDB 外部文件缓存处于开启状态。计时包含 execute 和 fetchone，不能解释成冷磁盘性能或纯 I/O 时间。

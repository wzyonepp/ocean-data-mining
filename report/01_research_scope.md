# 研究问题与研究边界

仓库：https://github.com/wzyonepp/ocean-data-mining

阶段：第二步——确定研究问题与边界。本文件为选题方案，尚未运行实验，也未形成性能结论。

## 1. 暂定题目

**面向两类浮标时序查询的 Parquet 排序顺序对照实验**

一句话描述：在同一份浮标时序数据上，固定分区方式、压缩算法、行组行数和查询引擎，比较“站点优先”“时间优先”两种排序对查询性能的影响，并分析查询需求变化时的排序选择依据。

对应课程内容：第二章第 3 讲的 Parquet 行组、数据跳过与物理排序，重点参考第 4、6、7、9 页（按 PPT 文件页序，含封面）。

## 2. 核心研究问题

固定数据内容和写入、查询条件后：

> 按 `(station_id, observation_time)` 排序与按 `(observation_time, station_id)` 排序，分别如何影响“单站点时间范围查询”和“跨站点时间窗口查询”的耗时与行组可跳过程度？

进一步探索：当两类查询的出现比例改变时，较优排序是否也会改变？能否据此形成一个简单、可解释的选择建议？

“较优”主要指相同查询结果下的查询耗时更低；行组统计用于解释原因。任何排序的优势均需结合数据分布和查询选择率说明。

## 3. 数据对象与两类查询

数据对象为多个海洋浮标站点的观测记录，最小字段如下：

| 字段 | 含义 |
|---|---|
| `station_id` | 站点标识 |
| `observation_time` | 观测时间，统一为 UTC |
| `sst` | 海表水温，统一单位为摄氏度 |

实际数据集及时间跨度尚待下一步筛选。优先使用可公开获取、允许用于课程实验的真实浮标数据。合成数据可辅助验证机制，但应单独标明，结论不能直接泛化为真实海洋数据规律。清洗、缺失值及重复记录处理统一在生成各布局之前完成。

| 查询 | 具体问题 | 筛选条件 |
|---|---|---|
| Q1：单站点时间范围查询 | 某浮标在一段时间内的平均水温是多少？ | 站点相等条件 + 半开时间区间 `[t0, t1)` |
| Q2：跨站点时间窗口查询 | 所选全部站点在某一时间窗口内的平均水温是多少？ | 半开时间区间 `[t0, t1)`，无站点筛选 |

两类查询均返回记录数量和平均水温，固定输出形式，减少结果传输量差异的干扰。每条查询在三种布局上使用完全相同的站点与时间参数，并记录实际匹配行数和选择率。

## 4. 对照方案

| 方案 | 行记录的物理排列 | 用途 |
|---|---|---|
| A：随机排列 | 使用固定随机种子打乱全部记录 | 无有序聚集的参考基线 |
| B：站点优先 | `station_id ASC, observation_time ASC` | 检验站点聚集的影响 |
| C：时间优先 | `observation_time ASC, station_id ASC` | 检验时间聚集的影响 |

三种方案包含相同的逻辑记录，差别仅在记录排列。B 与 C 是核心比较；A 用于辅助解释排序带来的变化。

## 5. 固定条件与研究范围

| 项目 | 初期边界 |
|---|---|
| 分区方式 | 统一不分区 |
| 文件组织 | 每种布局独立保存，初期各使用一个 Parquet 文件 |
| 数据内容 | 同一份清洗后数据、相同字段和类型 |
| 行组大小 | 按固定行数切分；具体数值在小样本试跑后、正式实验前锁定 |
| 压缩与编码 | 相同压缩算法和级别、字典编码及统计写入设置；具体参数待实验设计阶段确定 |
| 查询实现 | 使用同一查询引擎及版本；建议 Python + PyArrow 写入、DuckDB 查询，版本待后续确认 |
| 运行环境 | 同一存储介质、硬件、线程数和缓存处理方式 |
| 查询参数 | 各布局使用同一套查询集合，按统一方法重复测量 |

本题唯一改变数据物理布局的因素是排序顺序；查询类型、时间窗口和两类查询比例属于需要明确记录的工作负载条件。

**压缩算法相同，不代表文件字节大小相同。** 排序可能改变压缩率，文件大小应作为结果记录，不能靠调整行组、压缩参数等方式强行对齐。耗时差异也可能包含压缩率变化的影响，应结合扫描相关证据分析。

暂不研究分区优化、行组大小调优、压缩算法比较、小文件合并、Iceberg 清单剪枝、空间编码、分布式集群和预测模型。初期结论针对单文件内的 Parquet 行组布局，不直接推广到整个湖仓系统。

## 6. 待验证假设

以下是假设，不是实验结果：

- H1：当单站点记录足够多、可以在行组中形成有效聚集时，站点优先排序可能更有利于 Q1；实际效果还取决于站点数量、行组大小和时间范围。
- H2：对于覆盖全部站点的较短时间窗口，时间优先排序可能更有利于 Q2，因为不相交的行组可能更容易被排除。
- H3：随着 Q1、Q2 出现比例变化，整体耗时较低的排序可能发生变化；也可能在测试范围内始终由同一种排序占优。

## 7. 评价指标与判断方式

1. **正确性：** 三种布局在相同参数下应返回一致的计数和数值上等价的平均水温；浮点聚合采用明确的误差容限，不能要求逐字节相同。
2. **查询耗时：** 记录原始重复测量值，报告中位数及波动；比较两类查询各自的表现，并在需要时计算混合工作负载的平均耗时。
3. **扫描相关证据：** 优先记录引擎实际暴露的扫描指标；同时可依据行组 min/max 统计估算可排除行组比例。元数据估算的候选行组数不等同于引擎实际扫描行数或磁盘读取字节数，须区分标注。
4. **辅助指标：** 记录生成文件的字节大小，以及排序和写入耗时，说明查询收益的准备成本。

具体数据规模、时间窗口、重复次数与缓存处理方案，在后续实验设计及试跑后确定，正式对照前锁定并记录。

## 8. 候选原创探索与贡献边界

候选贡献是：用相同条件下的对照实验，识别两类查询中排序优势的适用条件，并尝试提出基于查询构成的排序选择建议。

仅验证“排序可能让查询更快”属于课堂机制复现。进一步探索可采用少量查询估计两种排序的表现，据此给出选择建议，再用预留查询检验建议并记录估计成本。是否采用这一扩展，由资料调研和试跑结果决定。

排序、工作负载驱动的布局选择均已有相关研究；目前不声称方法首创。原创性描述需要在资料调研后，具体说明自己在问题设定、海洋浮标场景、实验设计、边界分析或改进办法上的实际贡献。
